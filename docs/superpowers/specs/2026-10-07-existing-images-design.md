# 选择已有图片：设计文档

- 日期：2026-10-07
- 状态：设计已确认（用户选择"直接做并上线"）
- 基于：`2026-10-06-inline-edit-mode-design.md`

## 1. 目标

编辑表单里的图片字段（经历的 Logo、论文缩略图、项目和奖项的图片、头像）除了上传新图片，还可以直接选择网站上已经在用的图片，比如给新的经历复用已有的学校 logo。

## 2. 图片列表

- **来源**：编辑器手里已经有从 GitHub 读取的最新内容，从中收集所有图片字段的值。不发额外请求。
  - 哪些字段算图片字段，由表单定义决定：`LIST_SCHEMAS` 和 `PROFILE_SCHEMAS` 里类型为 `image` 的字段，以及表格字段里类型为 `image` 的列（联系方式的二维码）。以后新增的图片字段会自动包含在内。
  - 去掉空值，按路径去重，同时记下每张图片被用了几次。
  - 隐藏的条目也算在内。
- **排序**：
  1. 和当前字段同类的图片排在前面，例如在经历的 Logo 里，学校 logo 排在最前；
  2. 其余图片（头像、二维码等）排在后面；
  3. 每一部分里按使用次数从多到少，次数相同的按在内容里第一次出现的先后。遍历顺序是：先按 `LIST_SCHEMAS` 的集合顺序遍历各列表里的条目，再按 `PROFILE_SCHEMAS` 的顺序遍历个人信息。
- **字段的"类别"**：列表字段是 `<集合>.<字段>`（如 `experiences.image`），个人信息字段是 `profile.<字段>`（如 `profile.avatar`），表格里的列是 `profile.<字段>.<列>`（如 `profile.socials.qrCode`）。
- **新上传的图片**：保存后，它就出现在内容里，因此马上能被其他条目选用。部署完成前，缩略图用本次会话里的本地预览显示（沿用 `resolveImage`）。

## 3. 界面

- 图片字段的"上传图片 / 更换"按钮旁边加一个"选择已有图片"按钮。点击后在字段下方展开缩略图网格，按钮文字变为"收起"。
- **每张缩略图**：图片完整显示，下面是文件名，鼠标悬停时显示完整路径。字段当前的图片带紫色边框。
- **选择**：点一张缩略图，就把字段值设为这张图片的路径，并收起网格。
- **何时不显示按钮**：没有可选图片时（列表为空，或者只有当前这一张）。
- **表格里的小图片格子**（联系方式的二维码）空间太小，不加这个按钮，仍然可以上传。

## 4. 保存

选择已有图片只是把字段值设为该图片的路径（如 `/images/experiences/logo-hosei.png`），不会重新上传或复制文件，提交里只改 JSON。

## 5. 结构

- `editor/existingImages.ts`：`existingImages(content, kind)` 返回排好序的 `{ url, uses }` 列表。
- `editor/components/fields.tsx`：
  - `ImageInput` 增加可选参数 `choices`，有可选图片时显示"选择已有图片"；
  - `FieldControl` 增加可选参数 `imageChoices`，传给 `ImageInput`。
- `editor/components/ItemModal.tsx`：为图片字段计算类别和列表，传给 `FieldControl`。

## 6. 测试

- `editor/existingImages.test.ts`：
  - 用测试 fixture 验证排序：同类优先、次数多的在前、次数相同按出现先后；
  - 包含头像和二维码，忽略空值，按路径去重；
  - 没有同类图片时，所有图片按次数排序。
- 在模拟模式下用浏览器验证：
  - 经历的 Logo 字段能展开、选择、收起，选中后预览更新；
  - 保存后页面显示所选 logo，提交信息正常，没有上传文件；
  - 手机尺寸下网格不溢出。
